## Methodology Notes

- **Search coverage:** 21 web searches across official documentation, engineering blogs, and GitHub repositories. 16 returned primary-source evidence used in this report.
- **Could not verify:** Temporal Python error-handling docs (404 on multiple URL variants). Temporal's general durable-execution + retry + compensation model is well-known but the specific Python SDK docs were inaccessible. Recommendations reference Temporal at the conceptual level only.
- **No evidence found for:** Industry endorsement of DLQ for conversational AI / chatbot error handling (Medium #7). The absence of supporting evidence is reported as evidence of non-standardness, per the contrarian mandate.
- **Bias check:** This report focuses on what's *missing or suboptimal*. Design decisions that are sound are listed in the Appendix to avoid creating a falsely negative impression. The diff contains significant high-quality work (SCXML→UML revision, MCP upgrade, two-layer concept, structlog adoption).
